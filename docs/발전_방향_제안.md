# 「약속의 길」 발전 방향 제안 (2026-10-30)

지금 게임은 스토리·연출·음악이 이미 깊게 만들어져 있습니다. 반면 v9에서 클리어가 막혔던 것처럼, **새 내용을 넣을 때마다 어딘가 깨지는 구조**가 가장 큰 약점입니다.
그래서 순서를 **① 안 깨지게 → ② 손맛 → ③ 재미 → ④ 사람들에게 내놓기**로 제안합니다. 위에서부터 하면 다음 단계가 쉬워집니다.

---

## ① 안 깨지게 만들기 (가장 먼저, 1–2주)

| 할 일 | 왜 | 방법 |
|---|---|---|
| **git으로 버전 관리** | 지금은 zip으로 주고받아서 "어디서부터 망가졌나"를 알 수 없음 | GitHub 저장소 하나 만들고, 고칠 때마다 커밋. 이 맥은 먼저 `xcode-select --install`로 git 설치 |
| **자동 완주를 매번 돌리기** | v9 막힘은 테스트가 컷신을 통째 건너뛰어서 못 잡았음 | `tests/jplay.js`(v10에서 컷신을 탭으로 넘기도록 수정)를 고칠 때마다 실행. 나중엔 GitHub Actions로 자동화 |
| **스텝마다 "걸어서 도달 가능" 검사** | 자동 테스트는 순간이동을 해서, 대상 행렬처럼 걸으면 막히는 곳을 놓침 | 테스트에 "목표까지 걸어서 가기, 30초 안에 못 가면 실패" 모드 추가 |
| **조각 파일 → 장(章)별 파일** | `ep_sources/joseph` 조각 7개를 이어 붙여 2,000줄 한 파일을 만드는 방식은 고치기 어렵고 실수가 잦음 | 장마다 `ch1_pit.js`처럼 나누고 `build.sh`로 합치기 (구조는 그대로라 위험 적음) |
| **오류 보고 화면** | 사용자가 막혀도 원인을 모름 | 메뉴 → 설정에 "문제 신고" 버튼: 현재 스텝·위치·최근 오류를 복사해서 보내게 |

## ② 손맛 더 올리기 (웹판 그대로, 2–4주)

v10에서 멈춤·방향 전환·점프를 다듬었습니다. 다음 단계 후보입니다.

1. **실기기에서 감각 맞추기**: 아이폰·안드로이드에서 직접 해 보고 설정 → 「움직임 느낌」 세 단계(묵직/균형/경쾌) 수치를 조정. 숫자는 `js/motion.js` 맨 위 `M.FEEL` 한 곳에 모여 있습니다.
2. ~~**진동(햅틱)**~~ — v10에서 추가함(안드로이드). 아이폰까지 하려면 앱으로 감싸야 합니다(④ Capacitor).
3. ~~**상호작용 자석**~~ — v10에서 추가함.
4. **카메라**: 좁은 실내(보디발의 집, 옥)에서는 카메라를 자동으로 가깝게·높게. 대화할 때 두 사람이 다 보이게 살짝 옆으로.
5. **도구별 행동 모션**: 이번에 "들고 다니는" 모양은 잡았지만, 물 긷기·맷돌·낫질 동작은 예전 그대로. 동작마다 시작–타격–마무리 3단계로 나누면 훨씬 묵직해짐.
6. **발걸음 반응**: 모래·풀·돌바닥별 발소리는 이미 있음 → 물가에서는 물보라, 풀밭에서는 풀이 눕는 효과를 플레이어 주변에만 추가.

## ③ 재미 더하기 (콘텐츠, 1–3달)

- **선택의 무게**: 지금 대화 선택지는 대부분 정답 하나. 요셉의 성품(정직·용서·인내)을 고르는 선택이 이후 장면의 대사나 인물 반응을 조금씩 바꾸게 하면 다시 할 이유가 생김.
- **장별 다시 하기 + 기록**: 장 선택 화면, 장마다 숨은 수집품(애굽 말 단어, 성경 구절 카드)과 완료 표시.
- **미니게임 다듬기**: 맷돌·송아지·벽 새기기는 단순 연타·꾹 누르기. 리듬을 타거나 실패해도 재미있게(예: 송아지가 미끄러지는 연출).
- **다음 에피소드**: 요셉 편 뒷이야기(창 42–50장: 형들과의 재회·베냐민·야곱의 애굽 이주)가 자연스러운 다음 편. 엔진·인물·지도를 대부분 다시 쓸 수 있어 가장 적은 비용으로 큰 분량.
- **교육용 활용**: 교회 학교에서 쓸 수 있게 장 끝마다 "생각해 볼 질문" 카드, 교사용 진행 안내 PDF.

## ④ 사람들에게 내놓기

- **설치형 앱처럼 (PWA)**: 홈 화면에 추가, 오프라인 실행, 음악 캐시. 웹 코드를 거의 그대로 둔 채 앱처럼 쓰게 하는 가장 싼 방법.
- **앱스토어 출시가 필요해지면**: Capacitor로 지금 웹 게임을 감싸 iOS·안드로이드 앱으로 내기. Unity로 다시 만들지 않아도 됩니다.
- **피드백 받기**: 지인 10명에게 먼저 플레이시키고 "어디서 멈췄는지 / 어디서 지루했는지"만 묻기. ①의 문제 신고 버튼과 함께.

## Unity로 갈지에 대한 판단 기준

Unity로 다시 만드는 것은 사실상 **새로 만드는 일**입니다(렌더러·애니메이션·UI·스토리 진행을 C#으로 다시 작성, 수개월). 아래 중 하나가 꼭 필요할 때만 권합니다.
- 콘솔·PC 스팀 출시, 또는 훨씬 높은 그래픽(실사풍 조명·그림자·물리)
- 여러 사람이 함께 하는 멀티플레이
- 3D 모델러·애니메이터와 협업(지금은 모든 모델과 동작이 코드로 짜여 있어 외부 아트를 넣기 어려움)

그 전까지는 웹판을 다듬는 쪽이 같은 시간에 훨씬 많이 좋아집니다. 옮기게 되더라도 대사·스텝·지도 좌표·음악은 그대로 가져갈 수 있도록, ①의 "장별 파일 나누기"를 먼저 해 두면 이식이 쉬워집니다.
